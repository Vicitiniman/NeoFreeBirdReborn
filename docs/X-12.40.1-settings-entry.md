# Settings access correction — beta 72

The beta 71 device report identifies commit `f19e875` on X 12.40.1 build 1 / iOS 27.0.1. It records `native_system` as the preference, but the attached controller tree actually contains **T1TabbedAppNavigationViewController**, not the XNavigation glass owner. The glass adapter is `notObserved`, and the old settings entry records zero root appearances, row builds and button installs. A navigation preference is not evidence that its controller is active.

The screenshot shows the newer settings list. The supplied IPA contains `XSettings.SettingsListViewController` and `T1TwitterSwift.SettingsChromeViewController`; these are independent of the old `T1GenericSettingsViewController` entry. Beta 71's generic-controller and glass-only entry points did not cover this combination.

## Change

Beta 72 hooks the current settings list and chrome owners directly. Their root gets a visible **NeoFreeBird — Settings and customization** entry. Tapping it opens the existing tweak settings with the active native account, using the current navigation stack or a dismissible settings sheet. This route does not depend on the glass tab bar, its private ABI or a layout feature switch.

The entry reserves its own height through UIKit's [additional safe-area insets](https://developer.apple.com/documentation/uikit/uiviewcontroller/additionalsafeareainsets). It does not rewrite native settings rows, collection-view frames or scroll insets. Its padding changes only when its fitted height changes, including text-size and rotation changes. Root detection runs on appearance, when containment is known. A nested settings page does not receive another entry, and an entry moved beneath another settings owner is removed with its own padding restored.

The old settings row and the separate glass adapter remain available on their corresponding surfaces. Account credentials and saved sign-in storage are untouched.

## Diagnostics and validation

Reports now include `modernSettingsEntryRuntime`: callbacks by class, install/open counters, entry attachment, dimensions and owned padding. The controller tree uses identity deduplication, visits presented/visible controllers first and extends to depth 14 within a 96-controller budget. This addresses the old depth-six cut-off and repeated traversal of the same presented sign-in controllers. These additions do not export screen text or account identifiers.

Native regressions compile the production root-selection and layout helpers. They cover the current settings class names, mixed UIKit/custom containers, nested list/chrome ownership, 100 repeated inset calculations, height changes, safe restoration, landscape safe areas and zero-size transitions. These are model/layout checks; successful rendering and tapping on the affected iPhone still require a device test.

Source checks, Python/web tests, Swift/native regressions and the arm64 compile/link/package check are recorded in [PR validation](https://github.com/Vicitiniman/NeoFreeBirdReborn/pull/49/checks). No IPA is produced for this source update.

The first build after the older-iOS initializer follow-up (`a9fd4b9`) failed because `initWithTitle:image:primaryAction:menu:` is not declared by the build's iOS 16.5 SDK. The settings sheet now uses the standard system Done button with target/action and dismisses its own navigation controller. The source-only regression helpers do not compile UIKit presentation code; the complete iOS build is the validation for this correction.
