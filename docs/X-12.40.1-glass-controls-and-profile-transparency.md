# Glass controls and profile transparency — beta 76

The supplied report confirms beta 75 with a 400-point owned dock, 47 automatic collapse transitions and one material construction. The screenshots identify the reserved original navigation area, manual expansion being immediately reversed, an opaque profile overlay over the banner and the separate black follower-count row.

## Floating navigation and manual expansion

Liquid Glass mode removes the original phone navigation reservation through the native `visibleTabBarFrame` measurement. An empty frame is anchored at the native bar's bottom because X calculates its inset from the frame's minimum Y. Returning CGRectZero would reserve the whole screen. Native frames and cached frame updates remain unchanged; the supplied binary confirms the setter compares its stored ivar directly, so this getter does not create a repeating frame-update loop. Docked reply/media content retains its native reservation. Turning the design off restores the original measurement and interaction. The invisible stock view no longer intercepts timeline touches.

Tapping the compact button now overrides automatic minimization for the current page. Further downward drags, deceleration and replacement of the scroll view on that same page keep the tray open. Moving to a different page or tab resets the override. Upward scrolling still reveals an automatically minimized tray. Existing pinning and accessibility behavior remain respected.

## Appearance controls

**Appearance → Hide compose button** controls the blue floating plus button. It is off by default. Tracking is limited to the main navigation owner's verified floating action button; unrelated floating controls remain native. Native show requests respect the preference, and disabling restores native visibility, interaction and accessibility. When enabled, the compose button's frame factory avoids the owned dock so removing the old reservation does not cause overlap.

**Appearance → Glass opacity** opens a live slider from clear (0%) to opaque (100%), with a reset to clear. The fill behind the controls changes; icon and label alpha remain fully visible. Values persist, participate in preference profiles and reject non-integer/out-of-range values. Reduce Transparency keeps the surface opaque. No glass-effect rebuild is needed to adjust the fill.

## Profile repair

Beta 75 incorrectly converted native nil/clear header and summary backgrounds into opaque fills. These views overlap the banner. The theme now preserves native nil, clear and partial alpha, including through setters, attachment and theme notifications. Opaque content backdrops are explicitly registered instead. Banner/avatar geometry, masks and images are not modified.

Follower counts use a separate controller and drawing/background views. The dedicated counts/following row is themed separately, preserving existing alpha and excluding image/effect subtrees. Solid drawing colors use validated native getter/setter signatures and retain their native color for restoration. There is no generic composable-plane walk in post media.

## Validation

Native regressions cover the actual production manual-override state machine, same-page scroll-view replacement, page reset, native inset math and disable/docked-content guards. Surface tests cover clear and translucent banner overlays, independently registered backdrops, follower drawing colors and native restoration. Compose tests cover owner scoping, native show suppression, repeat refresh, deliberate native hides and button replacement. Opacity range/profile validation and compose/dock avoidance geometry are included. Existing navigation, sidebar, filtering and session regressions remain enabled. The PR records the complete iOS compile/link/package result; on-device rendering and touch behavior still require validation.
