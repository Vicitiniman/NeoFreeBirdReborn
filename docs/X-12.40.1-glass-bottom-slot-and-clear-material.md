# Liquid Glass bottom slot and transparent material — beta 77

The supplied beta 76 report has Liquid Glass enabled and opacity already at 0%. The screenshots show content ending above a solid bottom strip. The prior diagnostic `bottomReservationRemoved` described a requested layout policy, rather than measuring the actual container; it did not establish that the strip had disappeared.

## Remove the original phone bar

The X 12.40.1 container still allocated a physical navigation slot after its reported visible frame was changed. Beta 77 returns zero from `T1AppSplitViewController.private_bottomTabBarHeight` in supported phone overlay mode. X's own layout then sizes the stock navigation slot to zero and gives the space back to content. The whole native navigation rendering root is hidden, including private background descendants. The floating glass controls live as a sibling outside that hidden root.

The dock gets its geometry from the container and stock slot's origin instead of the now-zero native height. A parent layout callback refreshes it even when the hidden native child has no layout work. Native tab objects, selection entry points and routing are retained. Turning Liquid Glass off restores visibility and X's ordinary height. The iPad rail retains its existing layout.

The separate `tabBottomSegmentViewController` and its height remain native. When it contains a reply/media control, the floating dock sits above it; retaining that control no longer restores the unwanted navigation slot.

The supplied binary verifies `private_bottomTabBarHeight` as `d16@0:8`, `viewDidLayoutSubviews` as `v16@0:8` and `tabBarViewController` as `@16@0:8`. Its native bottom-slot frame subtracts both the navigation height and separate footer height. Diagnostics now distinguish the requested overlay from measured stock-root height/visibility, and include geometry of the last observed scrolling viewport when still attached. No text or account identifiers are captured.

## More transparent glass

**Appearance → Glass opacity** now controls the effect itself as well as the tint:

| Setting | Material | Theme fill |
| --- | --- | --- |
| 0% | Removed | Clear |
| 25% | Half strength | Clear |
| 50% | Full standard glass | Clear |
| 75% | Full standard glass | Half opaque |
| 100% | Full standard glass | Opaque |

The lower half scrubs a paused effect transition. At exactly 0% the effect is explicitly removed, so the old fixed frosted minimum is gone. Glyphs remain fully visible, with a light selection indicator and outline. The effect target is reused across slider updates, and the setting still persists. Reduce Transparency overrides the slider with an opaque surface.

The slider does not change the effect view's alpha: [Apple's UIVisualEffectView documentation](https://developer.apple.com/documentation/uikit/uivisualeffectview) warns that reducing the effect view or ancestor alpha can break effect compositing. The transition uses [UIViewPropertyAnimator](https://developer.apple.com/documentation/uikit/uiviewpropertyanimator).

## Validation and device check

Native regressions cover zero stock-slot sizing, full dock geometry with a zero-height root, separate footer clearance, repeated layouts without cumulative spacing, whole native-tree suppression, sibling control ownership, disable/reparent restoration and every percentage of the material/tint range. Existing routing, scrolling, compose, profile, filtering and session tests remain enabled. Source checks and a full iOS compile/link/package check run on the PR.

Compilation and the view stand-ins do not prove UIKit rendering on a device. Validate Home and Likes media with the tray expanded and collapsed: content should extend behind the floating controls to the normal system safe area, without the old solid strip. Compare 0%, 25%, 50% and 100%, then disable/re-enable the design. If a report is needed, beta 77 records the actual stock-root measurements and rendered effect state instead of a policy-only success flag.
