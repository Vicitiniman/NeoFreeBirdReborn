# X 12.40.1 glass navigation — beta 71

The supplied beta 70 report confirms X 12.40.1 build 1 on iOS 27.0.1, a restored account session and active media-download hooks. It records the **classic navigation preference**, but not the actual visible navigation controller tree. Class availability alone did not establish that the settings entry or custom tabs were reachable.

## Changes

| Area | Implementation |
|---|---|
| Native layout | Classic navigation is now off by default. X chooses its native layout; an explicitly saved classic preference is retained. |
| Glass tab bar | A separate adapter handles `XNavigation.TabBarController` and its concrete Swift `Tab` array. It calls the native `replaceTabs(_:selecting:)` method, so content and tab actions stay together. |
| Settings access | A NeoFreeBird gear destination is inserted among the first five glass tabs. It opens the existing settings controller in X's navigation. |
| Native settings page | Root detection handles a missing UIKit navigation stack. The existing settings row remains, with a named gear button as a second entry. |
| Custom order and visibility | The editor records glass descriptors and refreshes the active glass owner. Home stays first; selection is preserved when possible and falls back to Home when removed. |
| Likes | The glass destination creates the existing Likes/waterfall controller with the active account's native feed. It does not require a Bookmarks carrier in the glass bar. |
| Appearance | X retains its material, animation, badge and layout machinery. Custom tint is applied without installing an opaque replacement background. |
| Layout cost | Repeated layouts compare the native array identity and preference generation. Stable layouts do not rebuild descriptors or request another native replacement. |
| Account changes | Owned destinations receive new per-context identities. Cached descriptors and controllers from another account are not reused. |
| Diagnostics | Reports now include the glass adapter state, recognized pages, unknown-page count, ABI image match, settings-entry counters and a bounded visible controller hierarchy. No screen text, credentials or account identifiers are recorded by these additions. |

The gear is a permanent route to NeoFreeBird settings, rather than a removable editor item. Existing native tabs retain their original factories and actions. Unknown identifiers remain in X's array instead of being guessed or silently discarded.

## Native contract and validation

The supplied IPA defines the new model in **XServiceLibraries**, UUID `9779C106-B1DA-3E48-995D-4AEAAEA9574A`. The adapter checks that image, the exact supported app build, the exported replacement method and the runtime types/bounds of every assigned descriptor field. A mismatch leaves the native model untouched. Cloned destinations require a template with no custom long-press or associated re-tap action.

The arm64 bridge was checked against the supplied method's disassembly: the array occupies x0, the identifier's String occupies x1/x2, and the receiver occupies x20. The method retains the incoming array itself. Descriptor fields are discovered with Swift's [field-reflection implementation](https://github.com/swiftlang/swift/blob/main/stdlib/public/core/ReflectionMirror.swift), rather than fixed byte offsets.

The new Swift regressions compile the production adapter with concrete descriptor fixtures. They exercise ordering, lazy factories, selection, 100 unchanged layouts, hide/show restoration, account changes, fresh native snapshots and rejection of incompatible fields/actions. Native Objective-C regressions also exercise settings roots with and without a UIKit navigation stack. These fixtures validate model behavior, not UIKit rendering or a device launch.

Source invariants, Python tests, web-transaction tests, Swift/native regressions and the arm64 tweak compile run in [PR validation](https://github.com/Vicitiniman/NeoFreeBirdReborn/pull/49/checks).

## Device checks still needed

This update has not been exercised on an iPhone or iPad here. Confirm the gear opens settings, the expected native destinations remain reachable, changes in Edit navigation bar apply correctly, and Likes opens its waterfall feed. Native glass label visibility, scroll collapse, badges and iPad rail geometry require device observation; their old class probes do not prove compatibility with the new renderer.

If something remains inaccessible, beta 71's compatibility report will distinguish an unrecognized page identifier, rejected native descriptor, absent glass controller and a settings insertion that never ran. No account reset or IPA packaging change is required for these source changes.
